# Phase 6 capacity review — 2026-10-17

Status: independent read-only review; implementation and load acceptance pending.

A 30-minute 1 Hz quote stream plus 30 final bars requires about 1830 receipts,
before duplicates. phase6_intake_validation.py limits receipts/segments to 64.
phase6_start_validation.py also limits depth, list size, maps and total values;
these snapshots are reused in journal detach and prior-state/receipt/checkpoint
verification. Increasing one constant is insufficient. Journal binders persist
successively enlarged full bundles, and nested verification revisits full prefixes.

Proposed bounded work package, not a readiness claim:
1. Introduce an explicit capacity-v2 path with reviewed resource budgets through
   all nested validators and actual journal binders. Preserve v1 schemas/refusals,
   existing artifacts and canonical hashes. Do not silently widen historical v1.
2. Enforce cumulative plan.intake_limit_bytes at actual runtime intake. Existing
   validation only checks positivity; per-object storage limits are insufficient.
3. Execute the actual 30-bar handoffs with retained 1Hz quotes, distinct payloads
   and clock probes, duplicates and worst-supported payload sizes. Measure peak
   memory/disk, total work and worst callback/quote/admission latency against the
   existing five-second timing requirements. Preserve every observed record.
4. If bounded full-prefix processing cannot meet those requirements, design and
   independently review append-only chunks and cumulative authenticated checkpoints
   with verified incremental deltas. Do not substitute truncation or unverified caches.

The reviewer concluded that an incremental protocol is not logically required
before benchmarking the explicit bounded path, but raising limits alone cannot
establish readiness. No pilot duration or observation frequency is changed here.
No prospective evidence was generated by this review.
